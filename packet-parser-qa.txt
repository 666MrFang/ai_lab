## D. IPv4 parser 的实现模式

- 方法签名：const 成员函数，输入 (const uint8_t*, std::size_t)，输出全部

- 错误处理：就地 error = "..." + return false；错误串为纯英文小写短语
  （如 "invalid ipv4 ihl"）。上层 parse 用同一 packet.error 透传，不抛异常。
- 长度校验：每个阶段先用 constexpr 常量（如 minimum_ipv4_header_length = 20）

- 字节序：大端组装用 static_cast<T>(hi) << n | static_cast<T>(lo)；

- 偏移语义：parse_ipv4 返回相对 IPv4 头的 payload_offset，由调用方 parse
  加上 ip_offset。parse_ipv6 应沿用此范式。

## 5. IPv6 与 IPv4 的关键差异

| 维度 | IPv4 | IPv6 |
|---|---|---|
| 头长度 | 可变，ihl*4，有 options | 固定 40 字节，无 IHL/options |
| 版本 | 高 4 位 = 4 | 高 4 位 = 6 |
| 首 32 位 | version/IHL/DSCP/ECN | version(4)+traffic class(8)+flow label(20) |
| 长度字段 | total_length（含头） | payload_length（不含 40 字节头），值 0 可能表示 jumbogram |
| 校验和 | 有 header checksum | 无首部校验和 |
| TTL/协议 | ttl / protocol | hop_limit / next_header |
| 分片 | 基础头内有 flags/fragment offset | 基础头无分片字段，靠扩展头 |
| 地址 | 32 位 | 128 位 |
| 上层定位 | protocol 即 L4 | next_header 可能是扩展头，未必直接是 L4 |
| 地址字符串 | 点分十进制 | 需 RFC 5952 压缩（::）、最长零串、小写 hex |

其中地址字符串格式化是新增代码里最复杂的一处，不能照抄 ipv4_to_string。

## 6. IPv6 parser 的输入与输出

- 输入：const uint8_t* data 指向 IPv6 头起始（即以太网头之后，由 parse()
  传 data + 14）；std::size_t length 为剩余可用字节数。
- 输出（引用参数）：
  - IPv6Header& ipv6：填充解析结果；
  - std::size_t& payload_offset：相对 IPv6 头 = 40；
  - std::size_t& payload_length：上层载荷长度；
  - std::string& error：失败原因。
- 返回：bool（成功 true）。
- payload_length 取值决策：镜像 IPv4"用长度字段"的做法，但需处理
  40 + payload_length <= length 校验；当字段为 0（jumbogram/offload）时，
  建议回退为 length - 40。此点需在 plan 中明确，避免与 IPv4 语义不一致。

## 7. 错误处理如何保持一致

- 沿用 error = "..."; return false; 与空错误串表示成功，不抛异常。
